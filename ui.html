A real PostgreSQL — compiled to WebAssembly — runs inside this tab, with the app's own access policies (supabase-schema.sql) applied to it. Nothing is installed and no data leaves this browser.

Worth knowing:
• The first start downloads about 17 MB and takes a few seconds; later ones are quick and work offline.
• The database lives in this browser's storage, and another browser or device sees nothing. Clearing site data deletes it — and so, on its own, can the browser: storage is "best-effort" until granted persistence, which this app requests on first start. Settings → Local database shows what you got; Settings → Export keeps a copy either way.
• One tab at a time: a second tab writing the same files would corrupt them, so it will refuse to open instead.
• The address below is not verified — it is what the policies judge, so you can rehearse the access model as anyone. That is fine here and only here: the database is yours. Move to Firebase or Supabase before a second person is involved.

Supabase Setup:
1) Create a project at supabase.com
2) Authentication → Providers → Enable Google (add a Google OAuth client)
3) Authentication → URL Configuration → Redirect URLs → add this site's URL
4) SQL Editor → run the repo's supabase-schema.sql
5) Project Settings → API Keys → copy the Project URL and one key below
   Use the Publishable key (sb_publishable_…, under "Publishable and secret API keys") or the legacy anon public key (a long eyJ… JWT, under "Legacy anon, service_role API keys") — either works, this app accepts both formats. They're public by design; Row-Level Security is the boundary.
   Never use the Secret key (sb_secret_…) or service_role key here — this app runs entirely in the visitor's browser, so a secret key would hand every visitor unrestricted access to the whole database, bypassing Row-Level Security. Secret keys belong only on a trusted server, which this app doesn't have.

2) Firestore Database → Create database (production mode)
